The Svelte 5 compiler, in Rust.
Identical output.

rusvelte is a port of the Svelte 5 compiler and svelte-check to Rust. Every layer is checked against the official JavaScript tools: on four real-world codebases its compiled output is identical to Svelte 5.57.2's.

Same machine, warm runs. Compile times exclude file reading and use one thread; the compiler hasn't been profiled or tuned yet.

On Windmill, most of svelte-check-rs's 9.3 s is the TypeScript 7 type-check itself. In a full vite build, bundling, CSS tooling and preprocessors take most of the time, so whole builds speed up less than the compiler alone; both builds above came out identical to the official ones (apart from SvelteKit's build timestamp). Build times are single runs for Windmill and the median of three for the other app.

How it's verified

The port follows the official source function by function, and nothing counts as done until it matches.

An oracle for every layer

Node scripts run the official tool over a corpus and record its exact output, options included: ASTs, warnings, generated JS and CSS, TypeScript overlays, diagnostics.

Diff, group, fix

A Rust binary per layer reruns the same inputs, compares the output exactly and groups mismatches by their first differing line, so the biggest gap is always next.

Real code, not just tests

Svelte's own suites cover the edge cases. Windmill, Immich and bits-ui cover what people actually write: legacy components, runes classes, snippets, async.

Variants for coverage

Corpora are recompiled with dev, hmr, custom elements, injected CSS, runes forced on or off and TypeScript, to push the code down every path.

What's there, what's next

Working

  • Parser, analysis, warnings and errors
  • compile (client and server) and compileModule
  • CSS output, scoping and pruning
  • svelte2tsx and svelte-check-rs (with TypeScript 7)
  • A drop-in for svelte/compiler in Vite builds (Node binding)

Not yet

  • Source maps identical to the official ones (close, not exact yet)
  • Testing vite dev with hot reload
  • An npm release, then a native Rolldown plugin
  • Preprocessors still run in Node

Try it

In a Vite or SvelteKit app on Svelte 5.57.2, after building the package from the repository (see packages/rusvelte):

npm install /path/to/rusvelte/packages/rusvelte
NODE_OPTIONS="--import rusvelte/register" vite build

Anything rusvelte doesn't handle (other Svelte versions, some options, components with errors) falls back to the official compiler. RUSVELTE_VERIFY=1 compiles everything both ways and reports any difference.

svelte-check-rs

The project needs TypeScript 7 (@typescript/native-preview or typescript@7), as with svelte-check --tsgo.

cargo build --release --bin svelte-check-rs
cd my-app
/path/to/svelte-check-rs --tsconfig ./tsconfig.json

Options follow svelte-check: --workspace, --output, --threshold, --watch, --incremental, --fail-on-warnings and more. See the README.
